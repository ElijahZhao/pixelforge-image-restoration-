## 一、🔴 P0 — 安全

### F1 · 轮换与 .git/config 中暴露的 token
- **影响**：token 明文在 `.git/config`，且经第三方镜像 `ghproxy.net` 每次转发。可被读取者滥用推送权限。
- **具体做法**：
  1. GitHub → Settings → Developer settings → Personal access tokens → **Revoke** 旧 token；
  2. 生成新 fine-grained token（仅 `repo` 权限，限本仓库）；
  3. 本地：`git remote set-url origin https://github.com/ElijahZhao/pixelforge-image-restoration-.git`（**改回官方地址，不再走镜像**）；
  4. 后续用凭据管理器/环境变量注入，不写入 config。
- **预期效果**：暴露面归零。
- **验证方法**：`grep -E "ghp_|oauth2:" .git/config` **应无输出**。（已确认 token 从未进入 17 个 commit 历史，无需改写历史。）

## 二、🟠 P1 — 让模型真正"有效"（决定项目含金量的核心）

### F2 · 感知损失补上 ImageNet 归一化（单点性价比最高）
- **影响**：`VGGPerceptualLoss.forward` 直接把 `[0,1]` 张量喂给 pretrained VGG16，导致 **94.2% 特征退化为零**（第 3/11/13/15 轮实测）。感知损失实际在"接近全零"的特征上算差距，几乎无效。
- **具体做法**：在 `train/train.py` 的 `VGGPerceptualLoss.forward` 中，特征提取前加一行：
  `x = (x - mean) / std`，`mean=[0.485,0.456,0.406]`、`std=[0.229,0.224,0.225]`（对 pred 与 target 都做）。
- **预期效果**：VGG 特征均值从 0.05 恢复到 0.24（约 4.8×），感知项恢复有效信号。
- **验证方法**：写一个断言——同一输入，归一化后 `(feat==0).mean()` 应 **< 5%**（当前 94%）；且 `percep` 项数值不再接近零。

### F3 · 损失权重重平衡（`0.01 * loss` 这一行）
- **影响**：`loss = 0.01 * loss + percep(out, hr)`——像素项被乘小 100 倍，与感知项形成"两个错误互相掩盖"（第 11 轮）。模型实际优化的是"被归一化 bug 扭曲过的感知目标"。
- **具体做法**：改用显式加权，如 `loss = w_pix * charbonnier(out, hr) + w_per * percep(out, hr)`，`w_pix / w_per` 按论文惯例设 1:0.006 量级（Johnson 2016）或干脆 `w_per=0`（见 F4）。**关键是让权重可读、可记录，而不是藏在 `0.01`。**
- **预期效果**：像素项不再被抹除，PSNR 与观感可同时改善。
- **验证方法**：训练日志逐 epoch 打印 `w_pix*pix` 与 `w_per*per` 的**绝对值**，二者量级应可比、且随训练下降。

### F4 · SR ×4 去感知损失重训（PROGRESS §P1 已备命令，但需先修 F2/F3）
- **影响**：当前 SR×4 实测 **22.06 dB vs bicubic 33.25 dB（差 11.2 dB）**（第 10 轮），不是"取舍"而是"没训好"。
- **具体做法**：按 PROGRESS 已固化的 7 步命令，去掉 `--perceptual` 重训（纯 Charbonnier/L1）。**在 F2/F3 修好之前，不重训也比现在强。**
- **预期效果**：PSNR 预期升至 26+（文档自己的估计），压过 bicubic；观感略平滑。
- **验证方法**：**必须在本项目自己的验证划分上自测**，指标写入 `results/`（含 CSV），并用第 10 轮的评测脚本复现 ≥ 文档声称值。

### F5 · 训练目标与评估目标对齐（停训准则自洽）
- **影响**：开 `--perceptual` 时模型优化 `0.01*l1+感知`（感知主导），但选 best checkpoint 只看**纯像素 PSNR**（`evaluate_batch` 只返回 psnr/ssim）——两个方向可能相反，等于没有自洽的"何时停"（第 13 轮）。
- **具体做法**：三选一——(a) 训练无感知时用像素 PSNR 选 best（自洽）；(b) 有感知时用组合指标或 LPIPS 选 best；(c) 明确声明"best 按像素 PSNR 选，与训练目标不完全一致"并在日志标注。
- **预期效果**：停训准则可解释。
- **验证方法**：训练日志中 best 选择依据与损失构成**在同一文件可见**，二者不矛盾。

## 三、🟡 P2 — 能力真实性与叙述一致

### F6 · 补测并在仓库内存放可复现的真实指标
- **影响**：`results/` 仅含 README、**无任何训练日志/测量产物**；"真实评测指标 ✅100%" 无法从仓库复现（第 10/17/18 轮）。
- **具体做法**：训练后把 `results/train_log_*.csv` 与一份 `eval_on_testset.py`（在固定、非随机裁剪的验证集上算 PSNR/SSIM）**提交进仓库**；表格每行标注"自测/文献"来源。
- **预期效果**：所有数字**可证伪**——懂行的人能一键复现。
- **验证方法**：`git clone` → 跑 `eval_on_testset.py` → 输出与 README 表格数值吻合。

### F7 · 消除 SR×4 的"隐藏 4 倍假放大"
- **影响**：`serve/model_loader.predict_sr` 与两个部署入口：输入 512→内部降 128→模型产出 512→**再 PIL 插值放大到 2048 返回**。对外 2048，模型真实只做到 512，中间 4 倍是插值（第 10 轮）。"×4"名不副实。
- **具体做法**：模型真实输出即为 `lr*scale`；对外返回时**不要再用 PIL 二次放大到 `orig*scale`**，改为直接返回模型输出（即 `output = lr*scale`），并在 UI 标明"模型真实输出分辨率"。
- **预期效果**：SR 语义诚实，对比 slider 的前后尺寸关系自洽。
- **验证方法**：断言 `predict_sr(img,4).size == (img.w//4*4, img.h//4*4)`，即输出边长 = 输入下采样值 ×4，而非 `orig ×4`。

### F8 · ×2 静默回退显式化
- **影响**：无 scale2 权重，用户选 ×2 时静默跑 bicubic，UI 徽章只显示 ×4 状态、不提示（第 4/6/16/19 轮，`/api/health` 已诚实暴露 `sr_scale2: classical`，但 UI 隐藏）。
- **具体做法**：二选一——(a) 训练并导出 scale2 权重（补全）；(b) UI 在选中 ×2 时明确显示"×2 当前使用经典 bicubic 基线（无自训权重）"。
- **预期效果**：用户不会被"用 ML"的暗示误导。
- **验证方法**：选 ×2 时页面/响应可见明确的 engine 标注。

### F9 · 数据管线鲁棒性补丁
- **影响**：low/high 数量不一致 → `IndexError` 崩；损坏文件 → `UnidentifiedImageError` 崩；**low/high 尺寸不同 → 不崩但隐性错位**（同一 (i,j) 裁到不同区域，第 12 轮）。最后一种最危险——不报错的错误。
- **具体做法**：在 `datasets.py` 载入时**校验 low/high 文件名一一对应且尺寸一致**，不一致则跳过并 WARNING 计数；对损坏文件 try/except 跳过。
- **预期效果**：真实数据集上的"沉默错位"被拦截。
- **验证方法**：用第 12 轮的探针（数量不一致/损坏/尺寸不同三例）跑，应"跳过并告警"而非"崩溃或静默错位"。

## 四、🟢 P3 — 工程与文档一致性

### F10 · 叙述层对齐（把"取舍/胜出"改为可证伪表述）
- **影响**：README/PROGRESS 把 `0.01` 权重 bug 写成"刻意取舍"（第 1/3/11/13/17 轮）；"低光已验证胜出"建立在未自测参考带上、且项目自身样本反输 7 dB（第 10/18 轮）；README 状态表"指标✅100%"与同页 `TBD` 自相矛盾（第 17 轮）。
- **具体做法**：SR×4 行改为"PSNR 低于 bicubic，成因为感知损失实现缺陷（已定位），修复见 F2/F3"；低光行标注"基线为文献参考带，**未在本项目划分自测**"；状态表去掉"✅100%"改"部分完成（含 TBD）"。
- **预期效果**：文档**先于修复**变得诚实——这本身即加分项。
- **验证方法**：全文不再出现把已定位 bug 称为"设计选择"的表述。

### F11 · 统一部署文档
- **影响**：根 `DEPLOY.md` 整篇讲 Vercel+HF（已弃用），只字未提实际上线的 Streamlit；`DEPLOY_STREAMLIT` 与 `DEPLOY_HF` 互相矛盾（第 17 轮）。按 `DEPLOY.md` 会部署一套没人维护的栈。
- **具体做法**：根 `DEPLOY.md` 顶部加醒目声明"本文档含历史方案；**当前上线方案见 `deploy/streamlit/DEPLOY_STREAMLIT.md`**"，或直接重写为"Streamlit 主路径 + Vercel/HF 备选"。
- **预期效果**：读者拿到唯一权威部署路径。
- **验证方法**：四份文档对"哪个是主路径"给出一致答案。

### F12 · demo 图可复现（脚本与展示对齐）
- **影响**：`make_demo.py` 产出 `.png`，`assets/` 与 README 用 `.jpg`——"运行即可复现"不成立（第 18 轮）。
- **具体做法**：统一格式（要么脚本改存 `.jpg`，要么 README/assets 改引 `.png`）；重新运行脚本刷新展示图，确保仓库图 = 脚本产物。
- **预期效果**：`python scripts/make_demo.py` 真能复现 README 展示图。
- **验证方法**：运行脚本后 `git status` 显示 assets 图被更新（字节变化），且文件名与 README 引用一致。

### F13 · 推理服务加输入/资源限制
- **影响**：`serve/app.py` 无 `Content-Length` 检查、无最大尺寸、无超时；SR×4 输出随输入线性放大（4000×3000→766MB、6000×4000→1.5GB）；CORS 默认 `*` + 无认证无限速（第 14 轮）。
- **具体做法**：加 (a) 上传大小上限（如 10MB）；(b) 输入像素数上限（如 ≤ 4MP）；(c) 请求超时；(d) 生产 `ALLOWED_ORIGINS` 设白名单。
- **预期效果**：单请求无法 OOM。
- **验证方法**：上传超大图返回 413/422 且响应体不大；`/api/health` 或日志可观测拒绝计数。

### F14 · 测试从"形状"升级到"正确性"
- **影响**：全部单元测试只断言 shape/range/isinstance/batch-invariance，**无法抓任何真实 bug**（第 9 轮变异测试：注入 10 个致命错误只拦下 4 个，且拦下的全是"改形状"的）。
- **具体做法**：新增"正确性测试"——如：PSNR 对已知答案的数值断言、VGG 归一化后零占比上限断言、`predict_sr` 输出尺寸契约断言、loss 权重量级断言、数据管线配对一致性断言（覆盖 F2/F3/F5/F7/F9）。
- **预期效果**：把测试从"防崩溃"升级到"防学错"。
- **验证方法**：对 F2/F3 等注入同类变异，测试应**失败**（当前会通过）。

## 五、修复顺序建议（依赖关系）

```
F1（安全，独立）
  └→ F2 → F3 → F4（感知损失链：先补归一化 → 再重配权重 → 再重训）
        └→ F5 F6（对齐评估 + 补可复现指标）
  └→ F14（正确性测试，可尽早写，防回归）
F7 F8 F9 F13（独立，可并行）
F10 F11 F12（文档层，独立，建议先做——"诚实"不需要等 GPU）
```

**关键判断**：F10/F11/F12 **纯文档、零成本、立刻可做**，且"把已定位缺陷如实写出"本身就是懂行的人最看重的品质；F2/F3 是**单点最高性价比的技术修复**；F4 依赖 F2/F3 完成后再做才有意义。
