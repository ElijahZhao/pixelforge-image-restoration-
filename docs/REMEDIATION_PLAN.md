## 一、阶段 1 · 依赖清理

### 1.1 根 `requirements.lock.txt` 锁定为 CPU 构建

- **现状**：`requirements.lock.txt` 解析出 `torch==2.14.1`，连带 38 个 `nvidia-*` / `cuda-*` / `triton` 包。
- **影响**：CI 的 `pip install -r requirements.lock.txt` 每次都装这 38 个包（`ci.yml` 第 29 行）；
  `pip-audit` 审计的也是这一份（第 55 行），与部署实际安装的内容不一致。
- **改法**：
  1. `requirements.txt` 增加 CPU-only 索引与版本上限：
     ```txt
     --extra-index-url https://download.pytorch.org/whl/cpu
     torch>=2.0,<2.5
     torchvision>=0.15,<0.20
     ```
  2. 重新生成锁文件：`pip-compile --output-file=requirements.lock.txt requirements.txt`
- **验收**：`grep -cE "nvidia|cuda|triton" requirements.lock.txt` 结果为 `0`。

### 1.2 `deploy/streamlit/requirements.lock.txt` 删除

- **现状**：该锁文件同样是 `torch==2.14.1` + 38 个 CUDA 包；而 Streamlit 实际读取的是
  `deploy/streamlit/requirements.txt`（已固定 `torch>=2.0,<2.5` + CPU 索引），不读锁文件。
- **改法**：**删除**该文件。保留一份与实际安装不符的锁文件，比没有锁文件更容易误导。
- **验收**：文件不存在；`DEPLOY_STREAMLIT.md` 中若有引用一并移除。

### 1.3 `deploy/hf_space/requirements.txt` 补齐版本约束

- **现状**：`torch>=2.0` 无上限，安装时可能拉到 CUDA 构建。
- **改法**：与另两端对齐：
  ```txt
  --extra-index-url https://download.pytorch.org/whl/cpu
  torch>=2.0,<2.5
  torchvision>=0.15,<0.20
  ```
- **验收**：三端 `requirements.txt` 的 torch 约束一致。

## 二、阶段 2 · 验证管线修复

### 2.1 `train/datasets.py` · SR 验证集取消随机裁剪

- **现状**：`SuperResolutionDataset._load()` 内的 `torch.randint` 位于 `augment` 判断**之外**，
  验证集每轮裁剪位置都不同。实测 SR 验证 PSNR 极差 **7.35 dB**，而 200 轮的真实提升仅 **+0.46 dB**。
- **影响**：验证指标被噪声主导，`best checkpoint` 的选择不可靠。
- **改法**：随机裁剪只在 `augment=True` 时执行；验证集改为**中心裁剪**，保证确定性。
- **验收**：连续两次运行同一验证集，指标完全一致。

### 2.2 `train/datasets.py` · 低光验证集不再拉伸

- **现状**：`LowLightDataset.__getitem__()` 的验证分支在 `(w, h) != (crop_size, crop_size)` 时
  调用 `TF.resize(low, [128, 128])`。LOL-v1 图像为 400×600，会被压成正方形，
  横向压缩到 21%、纵向压缩到 32%。
- **影响**：训练期验证与 `scripts/eval_baseline.py` 的全图口径不一致，两组数字无法互相印证。
- **改法**：验证分支**不做长宽比拉伸**——保持原始尺寸；仅在小于 `crop_size` 时等比放大。
- **验收**：验证输出尺寸与输入长宽比一致；与 `eval_baseline.py` 口径对齐。

### 2.3 `train/train.py` · 验证使用与评测一致的预处理

- **现状**：训练期验证与 `scripts/eval_baseline.py` 各有一套预处理，结果不可比。
- **改法**：确认两处调用同一套验证预处理；差异处收敛到 `datasets.py` 单一实现。
- **验收**：同一权重、同一数据，两条路径给出的指标一致（允许浮点误差）。

> **注意**：本阶段会改变历史指标。旧数值保留于 `results/` 的既有日志中作为对照，
> 不覆盖、不删除。

## 五、阶段 5 · 权重复核（依赖阶段 2）

- **动作**：用修复后的验证管线重新评测现有两个权重，产出「旧口径 vs 新口径」对照表。
- **数据前提**：`data/` 下的数据集**不在仓库内**（`data/README.md` 说明不随版本保存）。
  本项需要先下载 DIV2K val（或复用训练时的同一份）与 LOL-v1 val，否则无法执行。
- **判据**：
  - 差异 < 1 dB：权重不受旧管线影响，仅更新 `results/` 记录。
  - 差异 ≥ 1 dB：best checkpoint 的选择受旧管线影响，**回报使用者**。

### 5.1 SR 权重 · **已判定需要重训**

不用等新口径复测就可以确定：旧日志后 50 轮的验证波动为 **2.15 dB**（标准差 0.5378），
而整个训练过程的真实增益是 **+0.46 dB**。噪声是信号的 **4.7 倍**，
`best checkpoint` 落在第 101 轮（27.39）而非第 200 轮（25.90）——这个选择由裁剪运气决定，不由模型质量决定。

因此 **SR ×4 权重与 ×2 一并纳入 AutoDL 重训**，不是只补 ×2。
重训脚本 `retrain_autodl.sh` 的 Step 3 已覆盖此项（验证现在走中心裁剪，指标可跨轮比较）。

### 5.2 低光权重 · **复核口径已改变**

旧日志后 50 轮极差仅 **0.22 dB**、标准差 0.0457，近乎一条直线（18.47 重复）。
这**不是收敛的证据，而是那个 bug 的症状**：400×600 被压成 128×128 后纹理细节大量丢失，
残差极小，图与图、crop 与 crop 之间的差异被一起抹平了。

"验证很稳"和"验证量到了东西"是两件事。修复后重测，判据仍是 1 dB：
- 差异 < 1 dB：低光权重可用，不重训。
- 差异 ≥ 1 dB：低光一并纳入 AutoDL 重训。
