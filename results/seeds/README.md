# 种子矩阵日志（阶段 4）

误差棒的原始出处。每个 subdirectory 是**一个种子的一次完整训练**：CSV 是逐轮日志，
JSON 是该次运行的参数 + 协议项 + 数据量 + 环境快照。权重（`.pth`）不入库，只在
`models/seeds/` 本地保留——但只靠这些 CSV 就能验证报告里的每一个数，因为
`val_psnr` / `val_ssim` 是逐轮的，不是只留最后一轮。

## 为什么这些 CSV 必须进仓库

论文里"5 个种子 × 3 个模型"的误差棒如果只有一张表，读者无法判断它是 5 次独立训练
还是 3 次里挑了 2 次。逐轮日志是唯一能自证"确实跑了 5 次、每次都跑满"的东西。

### 种子间变异 vs 协议变异（这两个数放一起才有意义）

| 来源 | 量级 | 出处 |
|---|---|---|
| 种子间 std（SRCNN ×2，n=5） | **0.069 dB** | 本目录 |
| 种子间 std（generator ×4，n=3） | **0.027 dB** | 本目录 |
| 退化算子换算（PIL ↔ torchvision+AA，×4） | **0.012 dB** | 协议对账 v3 |
| `antialias` 开关（×4） | **3.73 dB** | P5 28.95 → P6 25.21 |
| 全协议跨度（×4） | **2.26 dB** | 合成图冒烟，P1–P8 |

**种子根本不是这个量级的主导项。** 换 5 个随机种子，结果动 0.03–0.07 dB；仅仅把
`antialias` 从 True 改成 False，同一个 checkpoint 动 3.7 dB —— 差 50 倍以上。所以
"报告 5 个种子的均值 ± 标准差"是必要的诚实，但它回答不了"这个模型到底多少 dB"；
那个问题只有协议标签能回答。

## 四个读数陷阱

1. **30.686 不能和文献比，也不能和本仓对外表格的 32.35 相减。** 这是训练内验证：
   中心裁剪（96×96）、per-image mean、训练侧退化算子 `tv_bicubic_aa`。对外表格是
   全图 + `pil_bicubic`。两者差 1.66 dB 是口径差，不是进步，也不是退步。主表由阶段 5
   用 P1–P8 重评同一批 checkpoint 产出。
2. **`best == final`**：100 轮里最后一轮就是 val 最优。这批权重不适合演示
   "best-of-N 虚高"——那个现象来自随机裁剪口径（P1），不来自训练轮次。
3. **std 0.069 / 0.027 dB 是结论，不是缺陷。** 两个模型的种子间变异都远小于协议
   变异（见上表，差 50 倍以上）。**"种子敏感"这条论点在本项目里不成立**，别写成
   "种子带来的波动不可忽略"——数据不支持。真正要报的是"即使种子几乎不影响结果，
   换个协议口径能差 3.7 dB"，这比"种子敏感"更尖锐。
4. **generator 的 26.43 同样不能和对外表格的 27.47 相减。** 训练内验证是中心裁剪
   96×96，对外是全图 100 张，差 1.04 dB 是口径差。同一模型、同一权重，只是量的
   东西不一样。
